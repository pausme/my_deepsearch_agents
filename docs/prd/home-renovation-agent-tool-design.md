# 新房装修决策与预算管家 Agent 与工具改造方案

## 1. 改造目标

在当前 deepsearch-agents 项目基础上，将通用深度研搜助手改造成面向 C 端装修决策的垂直助手。

核心变化：
- 从“通用搜索报告”变成“装修消费决策报告”。
- 从“查资料”升级为“识别报价/合同/预算风险”。
- 从“结果文本”升级为“结构化风险项 + 可下载报告”。

## 2. Agent 架构

建议采用一主四从：

| 角色 | 职责 | 是否复用现有能力 |
| --- | --- | --- |
| 装修决策主智能体 | 识别需求、规划任务、汇总结论、生成报告 | 改造现有主智能体 |
| 公开资料检索助手 | 查询材料价格、装修流程、城市政策、避坑经验 | 复用网络搜索助手 |
| 报价单分析助手 | 解析报价单，识别漏项、重复项、价格异常 | 新增 |
| 合同风险助手 | 分析合同条款、付款节点、违约责任和增项风险 | 新增 |
| 知识库助手 | 检索内部施工规范、材料手册、合同模板 | 改造 RAGFlow 助手 |

## 3. 主智能体职责

主智能体不直接做所有细节分析，而是负责：
- 判断用户当前任务类型。
- 检查基础信息是否完整。
- 分派给合适的子智能体。
- 聚合互联网、报价单、合同、知识库结果。
- 生成普通用户能看懂的结论。
- 调用 Markdown/PDF 工具生成报告。

主智能体必须遵守：
- 先分析资料，再生成报告。
- 涉及价格必须给出范围和依据。
- 涉及合同必须提示仅供参考。
- 不输出绝对化承诺。
- 不直接推荐单一商家。

## 4. 子智能体设计

### 4.1 公开资料检索助手

输入：
- 城市
- 房屋面积
- 用户关注点
- 当前问题

输出：
- 市场参考信息
- 常见项目价格范围
- 施工流程建议
- 资料来源摘要

工具：
- `internet_search`

### 4.2 报价单分析助手

输入：
- 报价单解析文本
- 城市
- 面积
- 预算区间
- 装修方式

输出：
- 总价判断
- 单价异常项
- 疑似漏项
- 疑似重复项
- 模糊描述项
- 需要用户追问商家的问题清单

建议新增工具：
- `parse_quote_file`
- `normalize_quote_items`
- `compare_quote_with_reference_price`
- `detect_quote_risk_items`

### 4.3 合同风险助手

输入：
- 合同解析文本
- 报价单摘要
- 用户关注点

输出：
- 付款节点风险
- 工期风险
- 增项条款风险
- 材料替代风险
- 售后责任风险

建议新增工具：
- `parse_contract_file`
- `extract_contract_clauses`
- `match_contract_risk_rules`

### 4.4 知识库助手

输入：
- 用户问题
- 分析类型
- 当前风险点

输出：
- 施工规范
- 材料选购标准
- 合同审查模板
- 品牌或品类说明

工具：
- `get_assistant_list`
- `create_ask_delete`

## 5. 工具层改造

### 5.1 文件读取工具

现状：
- 已支持 txt/md/docx/pdf/xlsx/xls。

建议增强：
- 上传文件名安全清洗。
- 文件大小限制。
- 文件类型白名单。
- Excel 多 sheet 读取。
- 报价单表格结构识别。
- 图片型 PDF OCR 预留。

### 5.2 数据库查询工具

现状：
- 可列出表、预览表、自定义 SQL 查询。

必须改造：
- 禁止模型执行任意 SQL。
- 只允许 SELECT。
- 表名白名单。
- 字段白名单。
- 查询结果行数上限。
- 敏感字段脱敏。

建议新增领域表：
- 装修项目参考价
- 材料品牌档位
- 城市价格系数
- 常见漏项规则
- 合同风险规则

### 5.3 报告生成工具

现状：
- 支持 Markdown 生成和 PDF 转换。

建议增强：
- 固定报告模板。
- 结构化章节输入。
- 风险等级样式。
- 报告编号。
- 免责声明。

## 6. Prompt 改造方向

### 6.1 主智能体 Prompt

新增约束：
- 面向首次装修用户，语言要通俗。
- 所有建议按“原因、影响、下一步动作”输出。
- 报价分析不得只说贵或便宜，必须指出依据。
- 对缺少资料的情况，要先提出补充问题。
- 报告中必须包含免责声明。

### 6.2 报价单分析助手 Prompt

分析维度：
- 是否缺少拆改、水电、防水、墙地面、木作、安装、保洁等常见项目。
- 是否存在重复计费。
- 是否存在单位含混，例如“项”“批”“套”。
- 是否存在品牌、型号、规格缺失。
- 是否存在人工费和材料费边界不清。

### 6.3 合同风险助手 Prompt

分析维度：
- 付款比例是否前置过高。
- 工期延期责任是否明确。
- 增项确认流程是否书面化。
- 主材替换是否需要用户确认。
- 售后保修范围是否明确。

## 7. 推荐 MVP 实现顺序

1. 改造 Prompt，先把产品定位和输出风格调准。
2. 增加装修会话和文件元数据存储。
3. 加强上传文件安全和文件解析。
4. 增加报价单分析助手。
5. 增加结构化风险项输出。
6. 改造报告生成模板。
7. 增加 PDF 报告下载。
8. 补充接口测试和工具单元测试。

## 8. 第一阶段验收标准

- 用户可以创建装修分析会话。
- 用户可以上传报价单和合同。
- 系统可以读取文件并生成摘要。
- 系统可以识别至少 5 类报价单风险。
- 系统可以生成 Markdown 报告。
- 系统可以将报告转换成 PDF。
- 前端可以实时展示分析过程。
- 任务取消后前端状态正确。

## 9. 风险控制

必须加入的产品文案边界：
- 本产品提供装修决策辅助，不构成法律、财务或工程验收意见。
- 报价和价格范围仅供参考，实际价格受城市、材料、工艺、施工难度影响。
- 合同风险分析不能替代律师或专业监理审查。

必须加入的工程控制：
- 文件路径边界校验。
- 上传文件名清洗。
- SQL 白名单和只读限制。
- 用户数据隔离。
- 日志敏感信息过滤。
