# 新房装修决策与预算管家 PRD

## 1. 产品定位

产品名称：新房装修决策与预算管家

产品一句话定义：帮助准备装修或正在装修的用户，围绕户型、预算、材料、报价和施工方案，快速完成信息收集、方案对比、风险识别和报告输出。

产品形态：
- C 端 Web/小程序助手
- 对话式交互 + 文件上传 + 方案报告生成
- 支持 Markdown/PDF 交付

## 2. 为什么选这个场景

这个场景贴合真实消费决策，且复杂度足够高。

用户痛点很典型：
- 装修信息分散，平台内容、商家报价、合同条款、邻居经验都要看。
- 用户经常上传户型图、报价单、设计稿、施工合同，但看不懂。
- 最容易踩坑的不是“选哪个品牌”，而是预算失控、项目漏项、工期拖延、材料替代和增项争议。
- 用户需要的不是一个搜索框，而是一份能直接拿去和家人、设计师、工长沟通的决策材料。

这个场景和当前项目高度匹配：
- 互联网检索：查材料价格、施工工艺、装修趋势、政策。
- 结构化数据：查商品库、套餐库、价格区间、施工项目标准价。
- 私有知识库：查品牌手册、合同模板、施工规范、避坑文档。
- 文件上传：读报价单、户型图说明、合同、清单、预算表。
- 文件交付：生成可阅读的装修决策报告和预算清单。

## 3. 目标用户

核心用户：
- 首次装修的新房业主
- 有换房计划、正在做装修预算的人
- 想在设计师、工长、品牌门店之间做对比的家庭决策者

次级用户：
- 装修顾问
- 家装销售
- 社区团购或本地生活平台的家装运营人员

## 4. 核心问题

用户希望系统回答的不是单一问题，而是一个完整决策链：
- 我家适合什么装修风格和预算档位？
- 哪些项目是必须花钱，哪些可以后置？
- 这份报价单有没有漏项、重复项、明显虚高项？
- 主材和辅材应该优先看什么指标？
- 工期、质量、价格如何平衡？
- 如果预算不够，怎么删减才不伤核心体验？

## 5. 产品目标

业务目标：
- 降低用户装修决策门槛
- 提升报价单查看、方案生成和报告下载转化
- 帮用户把分散信息变成可执行方案

产品目标：
- 让用户 5 分钟内完成首次诊断
- 让用户 10 分钟内拿到可下载的装修分析报告
- 让用户愿意上传报价单、户型图、合同等材料继续深聊

## 6. 非目标

本期不做：
- 直接替用户下单
- 直接撮合施工交易闭环
- 复杂三维设计出图
- 实时工地监理
- 金融贷款审批

## 7. 核心使用流程

### 7.1 首次进入
1. 用户选择“新房装修”
2. 填写房屋信息：城市、面积、房型、装修阶段、预算区间
3. 选择关注重点：省钱、颜值、环保、工期、耐用
4. 系统生成初步诊断结论

### 7.2 上传资料
1. 用户上传报价单、合同、户型图说明、主材清单、设计稿
2. 系统自动识别文件类型并提取文本
3. 系统判断资料是否足够，并提示缺失内容

### 7.3 深度分析
1. 检索公开资料：材料价格、装修流程、常见坑点、政策
2. 查询结构化数据：标准价、品牌档位、项目对照表
3. 检索私有知识库：合同模板、施工规范、品牌说明
4. 对用户文件做逐项核查

### 7.4 输出结果
1. 生成“预算诊断结论”
2. 生成“报价单问题清单”
3. 生成“优先级建议”
4. 生成 Markdown/PDF 报告

## 8. 功能需求

### 8.1 需求采集
- 支持自然语言输入需求
- 支持表单补充关键字段
- 支持追问式补全信息
- 支持历史会话继续分析

### 8.2 资料上传
- 支持 PDF、Word、Excel、Markdown、图片说明文本
- 支持多文件上传
- 支持按会话隔离存储
- 支持文件列表查看和下载

### 8.3 智能分析
- 识别装修阶段和预算级别
- 识别报价单中的漏项、重复项、疑似增项
- 比较不同方案的价格区间和风险
- 提示环保、工期、施工顺序、合同条款风险
- 输出适合普通用户理解的结论

### 8.4 方案生成
- 生成简版结论
- 生成详细分析报告
- 生成适合分享给家人或设计师的 PDF
- 支持分章节输出：预算、材料、工期、风险、建议

### 8.5 实时可视化
- 展示智能体分析过程
- 展示正在调用的搜索、数据库、知识库和文件工具
- 展示生成中的文件和最终结果

## 9. 关键页面

### 9.1 首页/对话页
- 需求输入框
- 快捷场景入口
- 上传区
- 当前会话状态

### 9.2 分析过程页
- 任务进度
- 工具调用流
- 子助手调用流
- 错误与取消状态

### 9.3 报告页
- 总结结论
- 风险清单
- 报价单问题项
- 文件下载入口

## 10. 结果交付模板

报告固定结构建议如下：
- 一句话结论
- 当前装修阶段判断
- 预算健康度评分
- 报价单风险点
- 必保留项
- 可删减项
- 建议补充材料
- 下一步行动清单

## 11. MVP 范围

第一期只做：
- 装修需求问诊
- 文件上传解析
- 多来源检索分析
- 报价单初筛
- 报告生成与下载

第一期不做：
- 交易撮合
- 设计图自动生成
- 施工进度管理
- 商家入驻后台

## 12. 核心指标

业务指标：
- 首次会话完成率
- 文件上传率
- 报告下载率
- 二次追问率
- 7 日留存

产品指标：
- 首次诊断耗时
- 报告生成成功率
- 用户取消率
- 任务中断率

质量指标：
- 结论可读性
- 风险识别准确率
- 报价项覆盖率

## 13. 关键策略

- 首屏先给结论，不先讲方法
- 先收集预算和房屋信息，再展开分析
- 先提示风险，再给建议
- 报告必须能直接发给家人或设计师看

## 14. 风险与约束

- 报价单解析不完整会影响结论
- 家装价格强地域差异，价格建议必须带范围和前提
- 用户容易把“建议”误认为“标准答案”，必须在文案上明确边界
- 涉及合同和施工风险时，需提示“仅作参考，不替代专业审查”

## 15. 与当前项目的映射

该场景可直接复用当前项目能力：
- 主智能体：负责规划和汇总
- 网络搜索助手：查公开装修资料
- 数据库查询助手：查商品/价格/项目标准
- RAGFlow 助手：查装修知识库、合同和规范
- 文件工具：读报价单、合同、清单
- Markdown/PDF 工具：输出装修诊断报告

## 16. 结论

如果要基于这个项目做一个真正像样的 C 端产品，我建议优先做“新房装修决策与预算管家”。它足够真实、足够复杂、足够有消费价值，也最能发挥这个多智能体项目的优势。
